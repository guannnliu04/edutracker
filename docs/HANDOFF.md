研究所線性代數的**每日測驗系統**,以 iPhone 為主要使用環境:

1. 早上 8:00,ChatGPT 排程任務送來提醒與連結 `https://la-daily-quiz.vercel.app/quiz`。

## 4. 已實作的規則(精確版)

### 4.1 每日五題的配置
- **3 題**「基礎觀念 / 舊錯題複習」:到期的複習題優先(最多 3 題),其餘由基礎題補滿。
- **1 題**「最新章節」:從 `kind = chapter` 且章節 ≤ 目前章節的題目挑;沒做過的優先,目前章節優先。
- **1 題**「作業風格」:從 `kind = homework` 挑;沒做過的優先。
- 同一天不重複題目;同一天重新整理,題目與選項順序**不變**(以日期為種子)。
- **出題範圍:所有題目的章節都必須 ≤ 使用者設定的「目前章節」。** 範圍內不夠就少出。
- 基礎題挑選:近 7 天出過的延後;答錯次數多的觀念優先。

### 4.2 作答與提交
- 每題四選一(A/B/C/D 是顯示順序,內部用穩定的選項 id),可勾「不確定」。
- **全部作答才能提交。** 提交前,前端與資料庫都拿不到正確答案。
- **評分在伺服器端(Supabase 資料庫函式)進行**,前端不能自己寫對錯。
- 提交後不能再改答案。

### 4.3 複習排程(第 1、3、7 天)
- 答錯 → 排定「答錯日 +1、+3、+7 天」三次複習。
- **同一觀念只保留最新一組未完成的排程**(再次答錯會取代舊的)。
- 到期的複習題優先佔用當天最多 3 個名額。
- 複習出題:優先從**範圍內、同觀念、另一題**(變式)挑;沒有才重出原題。
- 已完成的複習會標記為完成。

### 4.4 弱點分析
- 弱點分數 =(答錯次數 + 0.5 × 答對但不確定)÷ 作答次數,範圍 0~1,越高越弱。
- 「遺忘」= 先前答對、之後又答錯的次數。
- 只列出至少錯過一次或答對但不確定的觀念;排序:分數 → 遺忘次數 → 作答次數。
- 顯示前 10 名;另有「近 7 天」摘要(正確率、不確定數、錯誤類型分布)。
- 統計合併:App 內五題 + GPT 匯入的練習紀錄。

### 4.5 題目來源與正確性規則
- **所有現有題目都標示「自編題」,不得冒稱歷屆作業原題。**
- 2015 / 2016 線代啟示錄作業只能當參考素材;標為「歷屆作業」的題目**必須附出處**(程式測試與資料庫約束都會檢查,否則一律是自編題)。
- 每題**恰好一個正確答案**:四個選項互不相同,資料庫層檢查正確選項存在於選項中。
- 解析**不可使用「選項 A / B」這類位置用語**(因為選項順序會被打亂),要用內容描述。
- 計算題須先用程式(numpy)驗算;純觀念題目前只靠推理,**沒有獨立驗算,也沒有對照教材**,且沒有欄位標示驗證程度(已知缺口)。
- **GPT 匯入的紀錄,對錯由 GPT 判定**,系統無法把關(只擋明顯矛盾,例如答案相同卻標答錯)。

### 4.6 目前題庫
- 20 題(9 基礎、6 最新章節型、5 作業風格),涵蓋第 1~8 章、17 個觀念,全為自編題。
- 章節:1 線性方程組與高斯消去、2 矩陣運算與反矩陣、3 向量空間與子空間、4 線性獨立 / 基底 / 維度、5 線性轉換與秩—零度定理、6 行列式、7 特徵值與對角化、8 內積與正交。
- 範圍越小可出的題越少(讀到前面章節時常少於五題),需要補題。

## 5. 技術架構(簡述)

- **前端:** React + TypeScript + Vite,手機優先,PWA(可加主畫面)。數學式用 KaTeX。
- **後端 / 資料庫:** Supabase(Postgres + Auth)。評分、複習排程在資料庫函式 `submit_session` 中執行。
- **API:** Vercel Serverless Functions(`/api/gpt/*`)。
- **部署:** GitHub → Vercel 自動部署;網址 `la-daily-quiz.vercel.app`。
- **主要資料表:** `questions`(題目,不含答案)、`question_keys`(答案與解析,前端完全讀不到)、`sessions`(每日測驗與草稿)、`attempts`(作答紀錄,由伺服器寫入)、`reviews`(複習排程,由伺服器寫入)、`settings`(目前章節)、`study_tasks`(讀書計畫)、`practice_logs`(GPT 練習紀錄,第二版)。
- **本機示範模式:** 沒設 Supabase 變數時用瀏覽器儲存,僅供開發;正式建置**排除**它,避免答案進入公開網頁。
- **測試:** 前端與 API 邏輯 143 項、資料庫權限與評分 46 項,皆通過(資料庫測試在 Claude 環境的本機 Postgres 模擬,**不是**使用者的真實 Supabase)。

### 資安模型(重點)
- 答案放 `question_keys`,無任何前端權限;只有 `submit_session` / `get_results` 在提交後回傳。
- `attempts`、`reviews` 只能由伺服器函式寫入;前端不能偽造或竄改。
- 每個使用者只能讀寫自己的列(RLS);匿名角色沒有任何權限;函式只開放給已登入者。
- 已登入的使用者本人仍可自行建立測驗並提交來看答案——單人系統,不在防護範圍。
- 網站程式檔已檢查:沒有答案、沒有舊版金鑰。

## 6. 與 GPT 的連接(第二版,尚未上線)

兩條路,互不依賴:

### 路線 A:手動匯入(不需要 ChatGPT 的 Actions)
GPT 練習結束後輸出下面格式的 JSON → 使用者複製 → 貼到 App「匯入」頁 → 按「驗證並匯入」。

### 路線 B:GPT 自動記錄(需要自訂 GPT 的 Actions 功能,**使用者帳號是否有此功能尚未確認**)
- GPT 出題前呼叫 `getStudyContext`;批改與檢討完成後呼叫一次 `recordPractice`。
- 金鑰驗證用一串使用者自己產生的隨機字串(Bearer)。
- 伺服器以「使用者本人」的身分存取資料庫,**不使用高權限的 Supabase secret key**。
- 代價:Vercel 環境變數會存使用者登入帳密,所以 Vercel / GitHub / Supabase 都該開 2FA(使用者說之後再做)。
- 風險:無請求頻率限制;金鑰外流時對方可寫入假紀錄、讀弱點與最近錯題。

### 紀錄格式(匯入頁與 API 共用同一套驗證)
```json
{
  "date": "2026-11-18",
  "items": [
    {
      "concept": "eigen-basic",
      "prompt": "矩陣 [[4,1],[2,3]] 的特徵值為何?",
      "options": ["1 與 6", "2 與 5", "3 與 4", "-2 與 -5"],
      "myAnswer": "C",
      "correctAnswer": "B",
      "correct": false,
      "unsure": true,
      "errorType": "calculation",
      "explanation": "tr=7, det=10,λ²-7λ+10=0 → λ=2,5。"
    }
  ]
}
```

### 驗證規則
- `items` 為 1~20 題;**任何一題不合格,整批退回**並指出第幾題哪個欄位。
- `concept`(1~60 字)、`prompt`(1~2000 字)、`myAnswer` / `correctAnswer`(1~500 字)必填;`correct` 必須是布林。
- `myAnswer` 與 `correctAnswer` 都是 A~D 字母時,`correct` 必須與兩者是否相同一致,否則退回。
- `errorType` 只能是 `concept` / `calculation` / `careless` / `guess`,且只有答錯才會被保留。
- `date` 格式 `YYYY-MM-DD`,必須是真實日期,不能在未來;不填就是今天(台北時區)。
- 同一天同一題重複匯入會被略過,不重複計算。

### 觀念 id(記錄時優先使用,否則用簡短中文名稱)
`linear-system` 線性方程組解的結構、`inverse` 反矩陣與可逆等價條件、`subspace` 子空間判定、`span-dim` 生成空間與維度、`rank-nullity` 秩—零度定理、`dim-formula` 子空間維度公式、`rank-ineq` 秩的不等式、`det-properties` 行列式性質、`eigen-basic` 特徵值計算、`diagonalizable` 可對角化判定、`eigen-functions` 特徵值與矩陣函數、`symmetric-spectral` 實對稱矩陣、`projection` 正交投影、`orthogonal-matrix` 正交矩陣、`idempotent` 冪等矩陣、`skew-symmetric` 斜對稱矩陣、`gram-matrix` AᵀA 與秩。

### 設計上的取捨(請讓使用者知道)
- 「五題交完才給答案」在 ChatGPT 對話中**只能靠指令約束,不是系統強制**。
- 計算題請 GPT 用 Python 工具驗算再出;GPT 判定的對錯仍可能有誤。
- GPT 匯入的題目一律視為「未驗證」。

## 7. 已知缺口與建議優先順序

1. **(已修,待上傳)** 出題範圍:基礎 / 作業風格 / 變式題不受章節限制。
2. **補題庫**:各章節題目不足,範圍小時會少於五題、很多觀念沒有第二題可當變式。
3. **題目驗證標記**:每題標示「程式驗算 / 已人工核對 / 未驗證」,加「回報此題有問題」。
4. **弱點 → 讀書建議**:把弱點排行轉成本週建議重點。
5. **「已讀完章節」細部記錄**(取代單一數字)。
6. **上線第二版**(GPT 匯入 / API / 資安收緊)。
7. 每日 AI 自動出題(需要另外決定:費用、如何驗證正確性)。
8. 離線作答、資料匯出備份。
9. 網站自行發送通知(PWA Web Push);iOS 鎖定畫面小工具 / Live Activity(需原生 App,系統穩定後再評估)。

**運行成本與限制:** Vercel、Supabase 皆為免費方案。Supabase 免費專案閒置約一週可能被暫停,需要使用者登入後台恢復。

### 提需求時的實務提醒
- **改複習規則要同時改兩處:** 資料庫函式 `submit_session`(正式環境)與前端的本機版邏輯(測試用)。資料庫那一份要使用者在 Supabase 重新執行 SQL 才會生效。
- **改出題規則**主要在前端選題邏輯,不需要動資料庫,上傳程式碼即可。
- **新增題目**只要寫進題庫檔並重新產生種子 SQL,使用者在 Supabase 執行一次。**題目必須附正確答案、解析,計算題要驗算。**
- 改動規則時,請說明**既有的歷史紀錄要不要沿用**(例如章節規則改了,舊紀錄是否重算)。
- 一次提少量、有優先順序的需求,比一次提大量需求更容易確認正確、也更容易上線。
