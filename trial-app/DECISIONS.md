# 工程決策紀錄(測試版採用的預設,可調整;未經使用者逐項確認)
| 項目 | 採用預設 | 理由 |
|---|---|---|
| N3 不確定範圍 | 只看基礎題 | 貼近 L1→L2「基礎穩固」的目的 |
| N7 Level 套用 | 每天(08:00)建立每日測驗當下算,只用已完成的有效日 | 當天題目固定 |
| N11 進階題位置 | 題庫格優先,其次進度格,不動基礎格 | 固定五題 |
| N13 寬限 | 6 小時(規格/SQL 原型已驗證;測試版以虛擬日運作,未模擬時鐘) | |
| N15 下一份的上一份來源 | 最近一份已提交測驗 | |
| N16~N19 | AI 題占比、預算上限、重試 3 次、去重 60 天;近似重複只用於 AI 手寫題 | 試用發現模板題套近似重複會全被擋 |
| N20 難度標籤 | 模板依矩陣大小;手寫候選自標;皆為「未校準」 | |
| 每日測驗每天一份 | 冪等;新的一天不覆蓋前一天未完成的 | 已確認需求 |
| 「完全不會」 | 錯誤類型含「完全不會」,弱點統計可分開看 | |
## 仍待使用者決定(會改變學習體驗,測試版先用預設)
N2 逐日 vs 合併、N4 反覆基礎錯誤定義、N9 L4 基礎題、N12 3/5 加強做法。
## 試用中發現並修掉的真實缺陷
1. 去重 content_hash 漏看預測式題型的選項 → 所有同模板題被視為相同。
2. 近似重複套在模板變式上 → 同觀念 7 天內完全出不了題。
3. 觀念挑選卡死在無供給的觀念 → 改為逐一換觀念,仍不足就如實少出並記錄。
4. 反矩陣模板的一個干擾選項用了浮點除法,渲染成 13333333333333333/1000000000000000000(手機試用截圖發現)→ 改用 Fraction,render.fmt 拒絕浮點數,並加全模板回歸測試。
